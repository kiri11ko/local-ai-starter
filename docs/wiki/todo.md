# Бэклог

## По результатам ревью 2026-11-09

Порядок: исправить P0 вместе с регрессионными тестами → укрепить установку и процессы (P1) →
провести реальные прогоны → улучшать рекомендации, измерения и структуру (P2).
Сохранить Python 3.9+, стандартную библиотеку, запуск через RunMe и интерфейс en/ru.
Ссылки на строки ниже относятся к состоянию кода на дату ревью.

### P0 — ошибки основных сценариев

- [ ] **Исправить миграцию каталогов моделей.**
  - Проблема: `migrate_layout()` переносит все каталоги, кроме `gguf` и `mlx`, в `models/gguf/`;
    актуальные `sd` и `tts` тоже переезжают. Подтверждено на временных файлах.
    Источник: `local_ai_starter.py:2301–2318`.
  - Как: мигрировать только явно известные старые каталоги; хранить версию раскладки данных.
    Продумать восстановление уже ошибочно перемещённых `gguf/sd` и `gguf/tts`: возвращать файлы
    без перезаписи конфликтующих файлов, конфликты показывать пользователю. Версию миграции
    фиксировать только после успешного завершения; повторный запуск должен быть безопасным.
  - Готово: тесты старой и текущей раскладки, повторного запуска, прерванной миграции и конфликтов;
    установленная медиа-конфигурация остаётся доступной после перезапуска без повторной загрузки.

- [ ] **Разделить выбор пользователя и состояние работающего сервера.**
  - Проблема: `ensure_installed()` перезаписывает `profile`, после чего `bring_up()` может принять
    сервер старой модели за уже запущенную новую. Подтверждено заглушками: выбран 9B, в состоянии
    остался `model_id` 4B, новый сервер не запускался.
    Источник: `local_ai_starter.py:2436–2438`, `1557–1561`.
  - Как: выделить `last_profile` и отдельную запись `server` с профилем, движком, model_id, PID,
    портом и временем запуска. Установка меняет только выбор пользователя; сведения о сервере
    меняет его жизненный цикл. Старое состояние мигрировать, неоднозначные сведения проверять.
    Повторно использовать сервер только после проверки его идентичности, конфигурации и здоровья.
  - Готово: переключения A → B, GGUF → MLX, код → медиа → код работают; повторный выбор A
    переиспользует A; бенчмарк подписан именем действительно запущенной модели.

### P1 — надёжность и проверяемость

- [ ] **Добавить автоматические тесты мастера и CI.**
  - Как: `unittest`, временные каталоги, заглушки процессов и локальный HTTP-сервер; тесты мастера
    держать отдельно от `test-cases/`, где проверяются модели. Начать с двух ошибок P0, затем
    покрыть докачку (206/200/416, обрыв, неверный SHA-256), безопасную распаковку, состояние,
    обновление и остановку процессов. Не требовать весов моделей и внешней сети.
  - Готово: единая команда проверки; CI на macOS/Linux/Windows, проверка Python 3.9 и актуальной
    поддерживаемой версии, ключей/параметров переводов и dry-run en/ru. Реальные движки проверяются
    отдельным ручным сценарием, а не объявляются проверенными по результатам заглушек.

- [ ] **Учитывать фактически установленные версии и ревизии.**
  - Проблема: llama.cpp, sd.cpp и OpenCode считаются установленными по наличию бинарника;
    MLX-модель — по наличию `.complete`, без сверки записанного commit.
    Источник: `local_ai_starter.py:198–201`, `1243–1287`, `2411–2419`.
  - Как: хранить манифест с версией, платформой, ревизией и проверенными хешами; сравнивать
    ожидаемое с установленным при построении плана. Для старых установок без манифеста не
    приписывать текущую версию автоматически. Показывать реальные версии на экране состояния.
    При изменении MLX commit сверять маркер; размер файла не считать доказательством идентичности.
  - Готово: смена закреплённой версии предлагает обновить нужный компонент; неизменные компоненты
    не скачиваются; смена commit модели обнаруживается; статус соответствует установленному.

- [ ] **Сделать установку компонентов восстанавливаемой после сбоя.**
  - Проблема: `_install_archive()` удаляет старую установку до распаковки новой.
    Источник: `local_ai_starter.py:1310–1318`.
  - Как: распаковывать рядом во временный каталог, проверять комплектность и запуск бинарника,
    затем переключать каталоги с резервной копией и откатом. Учесть блокировку исполняемых файлов
    Windows и необходимое свободное место; манифест писать после успешной установки.
    Для ZIP-обновления мастера также предусмотреть откат при частичной замене файлов
    (`local_ai_starter.py:2254–2283`).
  - Готово: ошибки распаковки, нехватка места и прерывание замены не уничтожают рабочую версию;
    повторный запуск восстанавливается и не принимает частичную установку за готовую.

- [ ] **Укрепить жизненный цикл процессов.**
  - Как: перед остановкой сверять PID с идентичностью процесса (время запуска/исполняемый файл),
    а не только его существование. После мягкой остановки и таймаута завершать принадлежащий
    мастеру процесс принудительно; очищать запись только после подтверждения остановки.
    Для тестовых команд управлять деревом процессов: отдельная группа на POSIX, подходящий
    механизм дерева процессов на Windows. При ошибке готовности очищать вновь запущенный сервер.
    Источник: `local_ai_starter.py:1499–1569`, `1750–1774`.
  - Готово: чужой процесс с повторно использованным PID не затрагивается; зависший сервер
    корректно завершается; таймаут/отмена теста не оставляют его дочерние команды работающими.

- [ ] **Провести реальные сквозные прогоны и опубликовать матрицу поддержки.**
  - Как: выполнить существующую задачу реальных прогонов ниже; дополнительно проверить код на
    llama.cpp и MLX, повторный запуск, переключение, остановку и обновление. На каждой заявленной
    ОС фиксировать версию ОС, архитектуру, железо, движок и результат; непроверенное обозначать явно.
  - Готово: результаты и ограничения в [status](status.md), воспроизводимые команды и журналы;
    основные README синхронизированы. Скачивание больших весов предварительно согласовать.

### P2 — качество продукта и сопровождение

- [ ] **Улучшить рекомендацию модели и контекста.**
  - Как: вместо одного правила «самая крупная по RAM» предложить «быстрее / баланс / качество»;
    учитывать доступную память, резерв ОС, стоимость KV-кэша, движок и наличие ускорения.
    При неизвестном железе использовать консервативный вариант и объяснять рекомендацию.
    Источник: `local_ai_starter.py:1445–1452`, `2372–2394`.
  - Готово: проверены типовые конфигурации 8/16/32/64 ГБ и CPU-only; рекомендованный профиль
    и контекст подтверждены реальными прогонами, пользователь может изменить выбор.

- [ ] **Сделать метрики сравнения однозначными и воспроизводимыми.**
  - Проблема: серверная скорость llama.cpp и MLX «выходные токены / всё время задачи» попадают
    в одну колонку. Источник: `local_ai_starter.py:2073–2082`.
  - Как: разнести серверные tok/s и сквозную производительность; неизвестные значения не заменять
    нулём. Сохранять версии мастера/движка, ревизию модели, хеш кейса, параметры генерации,
    контекст и железо; явно маркировать оценки по чанкам вместо токенов. Добавить повторные
    прогоны с медианой и разбросом, различать прогрев и холодный старт. Учитывать совместимость
    старого формата CSV. Проверку памяти Metal выполнить по существующей задаче ниже.
  - Готово: таблица не сравнивает разные величины под одним названием; любой результат можно
    связать с конкретной конфигурацией и повторить.

- [ ] **Разделить код на небольшие модули после покрытия основных сценариев тестами.**
  - Как: постепенно выделить каталог профилей, переводы/UI, загрузки/установку, состояние/процессы,
    обновления и бенчмарки. Оставить `local_ai_starter.py` точкой входа, сохранить RunMe и отсутствие
    внешних Python-зависимостей; передавать пути/настройки явно вместо разрастания глобального состояния.
  - Готово: прежние сценарии и CI проходят, обновление из ZIP доставляет все новые модули;
    архитектура и инструкции разработчика актуализированы.
