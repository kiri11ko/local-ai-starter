# Local AI Starter

[English](README.md) | Русский

Один двойной щелчок — и у вас локальный ИИ на своём компьютере: помощник для
программирования (llama.cpp или MLX, модель Qwen и OpenCode в терминале), генерация
картинок и видео (stable-diffusion.cpp) и озвучка текста (llama.cpp). Мастер сам скачивает
нужное и запускает. Набор тест-кейсов сравнивает скачанные модели на одних и тех же задачах.
macOS, Linux, Windows. Без облака, без ключей, без параметров командной строки.

Мастер говорит по-русски, если язык системы русский, иначе по-английски.

## Как запустить

- **macOS:** дважды щёлкните `RunMe.command` (в первый раз — правый клик →
  «Открыть», так просит Gatekeeper).
- **Windows:** дважды щёлкните `RunMe.bat`.
- **Linux:** `./RunMe.sh` в терминале (в файловых менеджерах — двойной клик, если
  разрешён запуск скриптов).
- **Вручную на любой системе:** `python3 local_ai_starter.py`.

Нужен Python 3.9+. Варианты выбираются стрелками **↑/↓** (или цифрой) и **Enter**.
Просто Enter выбирает рекомендованный вариант.

1. Мастер проверяет память и диск и спрашивает, что будем делать: код, картинки, видео
   или речь. Для кода на Apple Silicon ещё спрашивает движок (llama.cpp или MLX). Затем
   предлагает самую крупную модель, которая влезет в память.
2. План с размерами загрузок и одно подтверждение «Начинаем?».
3. Проверка, доступны ли GitHub и Hugging Face из вашей сети, затем скачивание
   движка, модели и OpenCode, запуск сервера и пробный вопрос.
4. Для кода OpenCode открывается в папке `local-ai/workspace`. Напишите задачу, например
   «Измени заголовок в index.html и добавь переключатель тёмной темы». Для картинок, видео
   и речи вы вводите описание (или текст для озвучки), файл попадает в `local-ai/outputs/`,
   и мастер предлагает его открыть. Пустая строка — назад.

Каждый следующий запуск начинается с меню: каждая скачанная конфигурация — отдельной
строкой («Запустить: Код · Qwen3.5 9B · llama.cpp», «Запустить: Картинки · Flux.1 schnell»…,
последняя запущенная первой), затем «Скачать новую конфигурацию», «Тест-кейсы» и меню управления.

После выхода из OpenCode (`/exit`) или из сеанса генерации появляется меню управления:
остановить сервер, оставить его работать, вернуться, другая конфигурация, тест-кейсы,
замер скорости, веб-чат в браузере (только llama.cpp), модели на диске, состояние и
журнал, удалить всё. `RunMe --menu` (или `python3 local_ai_starter.py --menu`) открывает
только это меню.

### OpenCode в своём проекте

Пункт меню «Команда для OpenCode в любой папке» создаёт команду `local-opencode` (небольшой
скрипт в `local-ai/bin/`) и, если вы согласитесь, ссылку на неё в `~/.local/bin` (Windows:
`%LOCALAPPDATA%\Microsoft\WindowsApps`). Дальше в любой папке терминала:

```
cd ~/my-project
local-opencode          # поднимает сервер с последней моделью и открывает здесь OpenCode
local-opencode --stop   # останавливает сервер модели
```

OpenCode работает с изолированными настройками из `local-ai/`, ваш собственный OpenCode не
затрагивается, мастер ничего не пишет в папку проекта. При выходе из OpenCode спросит, оставить ли
сервер работать. «Удалить всё» убирает и команду из `~/.local/bin`.

## Заблокированная или медленная сеть

Перед скачиванием мастер запрашивает у каждого сервера первый байт и ждёт до 15
секунд. Если сервер не ответил, мастер пишет, какой именно, почему (таймаут, DNS,
отказ в соединении, перехват TLS, ошибка HTTP) и что попробовать: другую сеть, VPN
или прокси через `HTTPS_PROXY`. Если загрузка замерла на 30 секунд, она повторяется
и продолжается с места обрыва. Всё скачанное сохраняется до следующего запуска.

## Что на диске

Всё лежит в папке `local-ai` рядом со скриптом. Больше нигде ничего нет: PATH,
конфигурации оболочки и ваши глобальные настройки OpenCode не меняются.

```
local-ai/
  engines/
    llama.cpp/    движок llama.cpp (закреплённая сборка, проверка SHA-256), в нём же llama-tts для речи
    mlx/          среда MLX на Apple Silicon: uv, свой Python 3.12, mlx-lm
    stable-diffusion.cpp/  движок картинок и видео (закреплённая сборка, проверка SHA-256)
  models/
    gguf/qwen/    модели GGUF для llama.cpp, по файлу на модель
    mlx/qwen/     модели MLX, по папке на модель
    sd/           файлы моделей картинок и видео; общие (VAE, текстовые энкодеры) лежат один раз
    tts/          файлы моделей речи
  opencode/       OpenCode CLI (закреплённая версия, проверка SHA-256)
  opencode-home/  собственные данные, сессии и кэши OpenCode
  opencode.json   настройки OpenCode: только локальная модель
  workspace/      папка, в которой работает OpenCode
  outputs/        сгенерированные картинки, видео и речь
  voices/         по желанию: образец голоса (см. «Речь»)
  test-runs/      каждый прогон тест-кейса: файлы модели, журналы, metrics.json
  test-results/   results.csv (все прогоны) и results.md (таблица сравнения)
  benchmarks.csv  результаты замеров скорости
  state.json, server.log, generate.log
```

Движки и их модели друг друга не перетирают. Удалить одну модель: меню → «Модели на
диске» (там же видны недокачанные). Удалить всё: меню → «Удалить всё, что скачано»,
или просто удалите папку `local-ai`. Сервер слушает только `127.0.0.1`.

## Модели

Линейка одна и та же для обоих движков, чтобы их можно было сравнить на одной модели.
Мастер рекомендует самую крупную, которая влезет в память.

| Модель | GGUF (llama.cpp) | MLX | Память |
|---|---|---|---|
| Qwen3.5 4B | Q4_K_M, 2,6 ГБ | 4 бита, 2,9 ГБ | 8 ГБ |
| Qwen3.5 9B | Q4_K_M, 5,3 ГБ | 4 бита, 5,6 ГБ | 16 ГБ |
| Qwen3.8 27B | Q4_K_M, 17,7 ГБ | 4 бита, 15,0 ГБ | 32 ГБ |
| Qwen3.6 35B-A3B (MoE, быстрая) | Q4_K_M, 19,0 ГБ | 4 бита, 19,0 ГБ | 48 ГБ |
| Qwen3.6 35B-A3B, 8 бит | Q8_0, 34,4 ГБ | 8 бит, 35,2 ГБ | 64 ГБ |

Контекст 32K токенов: 16K при памяти меньше 12 ГБ, 64K — от 48 ГБ. Одни только
инструкции OpenCode занимают около 10K. Это кандидаты, а не обещание скорости.

## Картинки, видео и речь

| Вид | Модель | Скачать | Память | Что умеет |
|---|---|---|---|---|
| Картинки | SD-Turbo | 4,9 ГБ | 8 ГБ | 512 px, 4 шага, самая быстрая |
| Картинки | Flux.1 schnell (Q4_K) | 9,7 ГБ | 16 ГБ | 1024 px, 4 шага |
| Картинки | Z-Image Turbo (Q8_0) | 10,4 ГБ | 24 ГБ | 1024 px, 8 шагов, читаемый текст |
| Видео | Wan 2.1 1.3B (Q8_0) | 7,3 ГБ | 16 ГБ | 33 кадра 832×480, 16 к/с, `.webm` |
| Видео | Wan 2.2 TI2V 5B (Q8_0) | 12,0 ГБ | 32 ГБ | 33 кадра 832×480, 24 к/с, `.webm` |
| Речь | Qwen3-TTS 1.7B (Q4_K_M) | 1,4 ГБ | 8 ГБ | 10 языков, включая русский, `.wav` |
| Речь | Qwen3-TTS 1.7B (Q8_0) | 2,1 ГБ | 16 ГБ | то же, голос чище |

Картинки и видео работают на stable-diffusion.cpp, речь — на `llama-tts` из той же сборки
llama.cpp, что и модели для кода. Каждая генерация — отдельный запуск движка, поэтому
первые секунды уходят на загрузку модели. Видео на Mac занимает несколько минут. Если
работает сервер модели для кода, мастер сначала останавливает его, чтобы освободить
память. Описания лучше писать по-английски. Речь выбирает русский, если в тексте есть
кириллица, иначе английский. Чтобы голос звучал как конкретный человек, положите запись на
5–15 секунд (`.wav` или `.mp3`) в `local-ai/voices/`.

## Тест-кейсы

В папке `test-cases/` лежат готовые задачи для сравнения моделей: стартовое меню →
«Тест-кейсы» → вид → один кейс или все → одна модель или все скачанные по очереди.

| Вид | Кейсы |
|---|---|
| Код | `cli-log-analyzer`: CLI-утилита с тестами по журналу веб-сервера; `fix-failing-tests`: найти баги, из-за которых падают готовые тесты; `landing-page`: лендинг с переключателем темы; `seo-audit`: SEO-аудит klukyanov.ru с загрузкой страниц |
| Картинки | `portrait`, `text-poster` (читается ли надпись), `complex-scene` (все ли предметы на месте), фиксированный seed |
| Видео | `cat-walk`, `city-pan` |
| Речь | `short-paragraph`, `russian-paragraph`, `long-article` (около 1,5 минуты) |

Всё замеряет мастер, а не модель про себя.

- Код: модель работает через `opencode run` в чистой папке, OpenCode сам одобряет её
  действия (только внутри `local-ai/test-runs/`). Пишутся: время, пиковая память сервера
  модели, токены на входе, на выходе, на размышления и из кэша, число вызовов инструментов
  (из событий OpenCode), а на llama.cpp — точные скорости чтения запроса и генерации по
  счётчикам сервера. На MLX скорость генерации — выходные токены, делённые на время. Затем
  идёт скрытая проверка: в трёх кейсах скрипт сверяет результат с правильным ответом
  (модель его не видит), в SEO-аудите проверяются обязательные разделы. Кроме того, каждый
  кодовый промпт просит модель написать `REPORT.md` о том, что она сделала.
- Картинки, видео, речь: время, пиковая память движка, секунды на картинку, на кадр видео
  или на секунду звука.

Каждый прогон лежит в `local-ai/test-runs/<дата>/<кейс>/<модель>/` (файлы модели в `work/`,
рядом `metrics.json`, `events.jsonl`, `answer.md`, `check.log`). В
`local-ai/test-results/results.csv` дописывается строка на прогон, а `results.md` показывает
последний прогон каждой модели рядом. Формат файла кейса описан в
[test-cases/README.md](test-cases/README.md): можно добавлять свои.

## llama.cpp или MLX

На Apple Silicon оба считают на видеоядре: llama.cpp через Metal, MLX — нативно.
MLX на Mac часто быстрее. llama.cpp работает на любой системе, и у него отлаженнее
вызов инструментов, на котором держится OpenCode. Чтобы сравнить их на своём компьютере:

1. Меню → «Другая конфигурация», выбрать «Код», движок и модель.
2. Меню → «Замер скорости». Он меряет чтение запроса (~4K токенов) и генерацию ответа
   (~300 токенов) и дописывает строку в `local-ai/benchmarks.csv`.
3. Повторить на другом движке с той же моделью и сравнить. И попробовать реальную задачу
   в OpenCode: скорость не всё, если вызовы инструментов не срабатывают.

## Обновления

При каждом запуске мастер сначала спрашивает у GitHub, не вышел ли новый релиз Local
AI Starter (не дольше 5 секунд; без интернета просто сообщает об этом и продолжает).
Если вышел, мастер показывает, что нового, и предлагает: **Обновить сейчас** (Enter),
**Не сейчас** или **Пропустить эту версию**. После обновления мастер перезапускается на
новой версии. Модели, движки и настройки в `local-ai/` обновление не трогает.

- Папка из git clone: мастер перематывает её на тег релиза (`git merge --ff-only`). Если вы
  сами меняли файлы, мастер их не трогает и советует `git pull`.
- Папка, скачанная ZIP-архивом: мастер скачивает архив релиза и заменяет свои файлы.
- Считаются только опубликованные релизы; незаконченная работа в `main` не предлагается.
- `--no-update` или `LOCAL_AI_STARTER_NO_UPDATE=1` отключают проверку.

## Настройки

| Переменная | Что делает |
|---|---|
| `LOCAL_AI_STARTER_LANG=en\|ru` | принудительно задать язык мастера |
| `LOCAL_AI_STARTER_HOME=<путь>` | хранить данные не в `local-ai/` |
| `LOCAL_AI_STARTER_DRY_RUN=1` | пройти сценарий без загрузок и запусков |
| `LOCAL_AI_STARTER_NO_UPDATE=1` | не проверять обновления при запуске |
| `HTTPS_PROXY` | стандартная настройка прокси, работает для всех загрузок |

## Границы

- Движки — CPU-сборки для Windows и Linux (на Mac используется Metal). Ускорение
  видеокартой на Windows/Linux пока не настраивается, поэтому картинки и особенно видео там
  медленные. Картинки и видео работают на macOS, Linux x64 и Windows x64.
- Пиковая память — это резидентная память процесса. С MLX на Mac она может учитывать не всю
  память видеоядра.
- Маленькие локальные модели заметно слабее облачных: рассчитывайте на простые
  правки, а не на большие рефакторинги.

## Чек-лист ручной проверки

macOS Apple Silicon, оба движка: чистый запуск → OpenCode правит `index.html` → `/exit` →
меню → замер скорости → смена движка → повторный запуск (в стартовом меню оба) → остановка →
«Удалить всё». Картинки, видео и речь: по одной генерации, затем по одному тест-кейсу каждого вида. Прерванная загрузка модели (докачка),
заблокированный хост (сообщение), занятый порт 8080, нехватка места. Linux и Windows —
на реальных машинах.
